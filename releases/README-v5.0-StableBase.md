# DIVA-Launcher v5.0 — 稳定基准版（阶段 0）

## 这一版做什么：**不提速，只求一直能玩**

它是 `DIVA-Launcher-v3.7-ForceFlip0.apk` 的**逐字节完全一致**版本，只是换了个名字。为什么这么做，下面讲清楚。

## 为什么退回 v3.7：一组对照数据说明一切

我把能拿到的三份实测日志放在一起，真相很清楚：

| 版本 | so | dex 配置 | 结果 |
|---|---|---|---|
| v3.7 | 无补丁 | v3.7 原始配置 | **出帧到 2700+，全程不卡死**，但帧率从 28 渐进掉到 12 |
| v4.1-Safe | 无补丁（同上） | 加了 d7 的 16 个变量 | 冲到 **54.6 FPS**，但玩一会卡死在 frame 360 |
| v4.3 | 无补丁（同上） | d7 变量改回两个 | 未验证 |

**三版用的是同一个 so，唯一差别是 dex**。v3.7 能一直跑，v4.1 快但会死。所以那些"提速变量"是有代价的——它们在高通 Adreno 735 上把系统带进不稳定路径。

v3.7 的稳定配置（从它的实测日志逐行读出）：

```
Output size 960x540                        ← 场景 960×540 再升采样
Texture quality: quarter                   ← 纹理 1/4（省显存带宽，关键）
BB_HONEST_LABELS=1                         ← 走已验证稳定的 fence 路径
BB_GUEST_IN_PLACE not 1 / UMA OFF          ← 不用 in-place 内存模型
vblank 60Hz，flip_rate=0，3 buffers，VSync off
BB_ASYNC_PIPELINES=0（4 线程异步编译）
```

而 v4.x 多加的 `BB_VK_SEGMENT_KB=64`、`BB_PRESENT_MODE=Immediate`、`BB_FRAMES_AHEAD=0`、`gsr2` 覆盖、`HonestLabels=0`、`GuestInPlace=1` 等，v3.7 一个都没有。**这些就是卡死的来源。**

## 老实说清楚取舍

- **v5.0 不快**：前期约 28 FPS，长时间玩会渐进掉到 12 FPS 左右（这是另一个独立问题，见下）。
- **但 v5.0 不会卡死**：出帧到 2700+，audio 全程正常，这是被你的真实日志记录下来的。
- 现在你手上如果装的是 v4.1/v4.3（快但卡死），**请先用 v5.0 换上，确认"能一直玩"这件事**，把它当作后续所有优化的基准线。

## 关于"渐进掉帧"（12 FPS 那个问题）

v3.7 日志里帧率从 28 掉到 12，对应官方 shadPS4 Issue #4215 记录的**长时间游玩渐进式帧率退化**——根源在 readback / 纹理缓存回收路径，属于**渲染器内部机制**，不是 dex 开关能修的。这正是研究报告里"阶段 2 要补的引擎级优化"。

## 下一步路线（研究报告里的完整版见 `PS4AOT性能优化研究报告.md`）

1. **阶段 0（本版）**：稳定基准，先能一直玩。✅
2. **阶段 1**：在稳定基准上逐项打开本地已有的提速机制（`BB_DRAW_PIPE` 等，本地 two-stage draw pipe = 官方 submit_draw_interval 的等价实现），每项单独 A/B。
3. **阶段 2**：补官方核心机制——`fast_shader_math`（本地有骨架，改动小收益全局）、pipeline cache、marker 跳过 + PGO/LTO。**构建依赖已确认齐全**（Boost 1.92 / NDK clang / fsr-vulkan / imgui 都在），可重编译 so。
4. **阶段 3**：内建量化计数器，每版用数据说话，不再靠"感觉"。
