# Turnip 驱动修复版 — AHB swapchain 崩溃修复

## 这个修复解决什么

真机日志里的失败：

```
AHB swapchain [0]: RGBA8 ...: getProperties failed (ErrorInvalidExternalHandle)
vk_swapchain_ahb.cpp:233 CreateBuffer: Assertion Failed!
STOP: GPU library assertion failed
```

根因：真机原来用的 Turnip **26.3.1-lto**（nihui 通用版，17.6MB）在当前系统的 gralloc 上无法从 AHardwareBuffer 导入 dma-buf——驱动里 `u_gralloc` 靠 `'gmsm'` magic 判断 buffer 是否 Qualcomm 分配，新版 gralloc 不再带这个 magic，导致 modifier 没被正确设置，AHB 属性查询返回 `VK_ERROR_INVALID_EXTERNAL_HANDLE`。

本修复版驱动基于项目验证过的 Mesa 配方（commit `35b085c`，26.3.0-devel）重新编译，并额外打入了 **u_gralloc "always use UBWC detection path"** 补丁（去掉失效的 gmsm magic 门禁，无条件计算 modifier），同时含 `0010` lazy `hw_get_module` 补丁（避免 NEEDED libhardware.so 导致 app namespace dlopen 失败）。

## 驱动信息

| 项 | 值 |
|---|---|
| 文件 | `libvulkan_freedreno.so`（13.7 MB） |
| Mesa | 26.3.0-devel @ 35b085c |
| 加载入口 | **HMI**（`HMI` 符号，HAL 直载）+ `vk_icdGetInstanceProcAddr`（双入口） |
| NEEDED | liblog, libnativewindow, libsync, libm, libz, libdl, libc（**无 libhardware.so**） |
| 目标 | Android arm64, API 30, Adreno 6xx/7xx（含 735）, 8xx |
| SHA256 | 见 `BUILD-INFO.json` |

## 部署步骤（真机）

真机从这条路径加载驱动（来自日志）：

```
/data/user/0/com.divaft.launcher/files/vulkan/libvulkan_freedreno.so
```

`data/user/0` 即 `data/data`。用 adb（需 root 或 app 可写）替换：

```bash
# 1. 先备份原驱动（重要，便于回退）
adb shell "cp /data/data/com.divaft.launcher/files/vulkan/libvulkan_freedreno.so \
           /data/data/com.divaft.launcher/files/vulkan/libvulkan_freedreno.so.bak"

# 2. 推送修复版
adb push libvulkan_freedreno.so \
    /data/data/com.divaft.launcher/files/vulkan/libvulkan_freedreno.so
adb shell "chmod 0644 /data/data/com.divaft.launcher/files/vulkan/libvulkan_freedreno.so"

# 3. 清掉可能的旧 stage（launcher 会把 data 目录里的驱动 stage 到私有目录）
#    如果 launcher 也读取自身 data 根目录的 libvulkan_freedreno.so，一并替换：
adb push libvulkan_freedreno.so \
    /data/data/com.divaft.launcher/files/libvulkan_freedreno.so

# 4. 重启游戏/app，观察是否越过 AHB swapchain 阶段
```

如果 app 有"选择/放置驱动"的入口，也可以直接把本文件放到 app 数据目录，让 launcher 自行 stage（见 `divadiag.c` 的 staging 逻辑）。

## 验证是否成功

重启后看 `diva-boot.log` / logcat：

- **成功**：不再出现 `getProperties failed (ErrorInvalidExternalHandle)` 和 `CreateBuffer: Assertion Failed!`，游戏继续推进到渲染/音频阶段。
- **仍失败**：请把新的完整 `diva-boot.log` 发回，重点看是否变成别的错误（比如 `No compatible AHB mem types`、`Failed to import dma-buf` 或 `has no GPU usage`），据此再定位。

## 回退

```bash
adb shell "cp /data/data/com.divaft.launcher/files/vulkan/libvulkan_freedreno.so.bak \
           /data/data/com.divaft.launcher/files/vulkan/libvulkan_freedreno.so"
```

## 诚实说明

- 本修复基于 upstream（whitebelyash / StevenMXZ 的 V37 recipe）针对 Qualcomm gralloc 的已知补丁，逻辑上对症，且已确认编入产物、符号/依赖兼容真机加载路径。
- 但**我无法在这个沙箱里连接真机验证**，所以需要你真机复测确认。若仍失败，日志会告诉我们是同一根因（则可能需要换驱动变体或改 swapchain 后端）还是新根因。
- 版本从 26.3.1-lto 变为 26.3.0-devel（去掉 LTO），若你依赖 26.3.1 的某些行为，可反馈。
